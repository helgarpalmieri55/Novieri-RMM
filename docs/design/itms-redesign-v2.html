ITMS console · design direction v2 · 7 September 2026

Signals, not a spreadsheet

v1 was text and rectangles, and it read like a database client. This pass replaces the numbers with things you can see, and takes the command line out of the form.

The two notes on v1, taken literally

v1

“Just text and squares, like a db table”

Correct. Every value was a glyphless string in a cell. Nothing had a shape, so nothing could be read at a glance, which is the only way an operations console is ever read.

v2

Every number gets a shape

286 devices become a 286-cell wall you can spot the red in. Trends get sparklines. Compliance gets arcs. Job runs get a timeline. Rows get OS marks, owner faces, and a bar for how far behind they are.

v1

“Who sets up a schedule using cron in a UI?”

Nobody. That field was the CLI leaking through the form. It also cannot be checked by eye: a typo in a cron string is invisible until the window silently never opens.

Maintenance window  [ 0 2 * * SAT ]
v2

You paint the window on a week

Seven rows, twenty-four columns, drag to select. The window is the picture, so it is right or obviously wrong. The console still stores cron; the operator never types it.

Icons are real: Tabler Icons (MIT) and their brand set, vendored as an inline sprite. None are hand-drawn, which the skill bans outright. Simple Icons no longer ships Windows or Ubuntu marks after trademark requests, so those come from Tabler's brand set instead.

Where else the command line is showing

The cron box was the worst one, not the only one. Same test applied across the console: is this control a form, or is it a shell prompt wearing a border?

Maintenance window0 2 * * SAT Week grid you drag. Cron is stored, never typed.
Device group rulesJSON rule object Condition builder, with the matching count updating as you build it.
Subnet entry10.20.4.0/24 CIDR is fine here, but show the usable range and count beside it as you type.

Every row is the same defect: a backend representation shown directly to a person. The storage format is not the interface.

Still true from v1

The structural finding has not changed, and it is still the larger half of the work: 65 pages, eight archetypes, 28 of them the same one built 28 ways. The visual direction above is what those eight components should look like; the coverage map and the adoption cost are in docs/design/itms-redesign-2026-09.html.

This remains a mockup. docs/design/itms-prototype.html is the design authority, tokens.test.ts and base-styles.test.ts enforce it, and nothing here reaches the product without moving the prototype first.
