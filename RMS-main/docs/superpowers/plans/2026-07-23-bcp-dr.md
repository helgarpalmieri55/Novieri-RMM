# BCP / DR Test Reports (Phase 10) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the control-plane BCP/DR module — DR plans with a review cadence, manual test execution records that freeze a point-in-time backup restore-test evidence snapshot, findings with remediation + org-scoped Change linkage, and SOC 2 test reports — with zero agent/worker footprint.

**Architecture:** A new `bcp` business module registering into the kernel like `change_mgmt` (models, migration, services, reporting, api, register_all) — **no agent jobs, no worker, no gateway registration**. It reads restore-test evidence from the backup module's existing reporting layer (read-only), resolves plan scope to devices org-scoped, and links findings to Change records via the same cross-org-safe resolution pattern change management uses.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy 2 (async), Alembic, Pydantic v2; React+TypeScript+Vite+vitest. venv at `backend/.venv`.

## Global Constraints

Every task's requirements implicitly include this section. Copy exact values verbatim.

- **No agent path / no worker.** This module dispatches NO agent jobs and registers NO job types; it has NO Celery sweeps and NO beat entries. Do NOT touch `register_worker_job_types`, `app/gateway/main.py`, or the job engine. `register(app)` only mounts the router (no `register_job_types()`).
- **Security invariant #4 — audit.** EVERY privileged action writes the hash-chained audit log via `audit_service.record(session, *, org_id, actor_type, actor_id, action, target_type, target_id, metadata)`. Actions + targets: `bcp.plan_created`/`bcp.plan_updated`/`bcp.plan_reviewed` (`target_type="bcp_plan"`, `target_id=str(plan_id)`); `bcp.test_created`/`bcp.test_recorded` (`target_type="bcp_test"`, `target_id=str(test_id)`); `bcp.finding_created`/`bcp.finding_updated` (`target_type="bcp_finding"`, `target_id=str(finding_id)`); `bcp.report_exported` (`target_type="bcp_test"` or `"bcp_period"`). All `actor_type="user"`, `actor_id=ctx.user_id`. No secret in metadata. A plain read/report VIEW writes NO audit — only an explicit export route does (the Phase-9 no-audit-on-view lesson).
- **Security invariant #5 — tenancy.** EVERY `select()`/write over `bcp_plan`/`bcp_test`/`bcp_test_step`/`bcp_finding` AND the cross-module reads (`change_request`, `devices`, `device_groups`, `doc_articles`) carries an explicit `org_id` predicate in addition to RLS. RLS is `ENABLE + FORCE` + a `tenant_isolation` policy `USING (org_id = current_setting('app.current_org', true)::uuid)` on all four new tables. A cross-org asset/change/doc reference is rejected at write time by an org-scoped existence check. A missing tenant filter is a security bug.
- **Security invariant #6 — RBAC.** Server-side `Depends(require_permission("<code>"))` on every route. Permissions: `bcp.read`, `bcp.manage`, `bcp.approve`. Grants: super-admin/org-admin → all three; technician → read+manage; auditor/read-only → read. `bcp.approve` NOT granted to technician. The 3 codes go in BOTH the migration seed AND `app/core/rbac.py` `PERMISSIONS` (the Phase-7 lesson).
- **Cross-org resolution guard.** Any reference to another entity — plan `scope` device/group ids, `procedure_refs` doc ids, finding `change_ref` — is validated by an org-scoped existence check `select(Model.id).where(Model.org_id == org_id, Model.id == ref_id)`; a nonexistent OR cross-org id resolves to None → `BcpValidationError`. Mirror `app/modules/change_mgmt/links.py`.
- **Typed not-found for 404 routing (Phase-9 lesson).** Define `BcpValidationError` and a subclass `BcpNotFoundError(BcpValidationError)`. The "row not found in this org" raises `BcpNotFoundError`; validation/bad-reference raises `BcpValidationError`. The API `_http_error` routes by `isinstance` — `BcpNotFoundError` → 404, else `BcpValidationError` → 400. NEVER a 500 on either. NEVER message-string matching.
- **Evidence snapshot is frozen.** When a test's execution is recorded, capture the backup restore-test evidence for the plan's covered devices into `bcp_test.evidence` as a point-in-time snapshot — a later backup change must NOT alter a recorded test's stored evidence.
- **Backup evidence is READ-ONLY.** Use `app.modules.backup.reporting.backup_evidence_rows(session, org_id) -> list[dict]` (per-device: `device_id`, `hostname`, `covered`, `last_backup_taken_at`, `verified_at`, `restore_tested_at`, `restore_proven`). BCP writes NOTHING to the backup module.
- **State vocabularies (verbatim).** `bcp_plan.state` ∈ {active, archived}. `bcp_test.type` ∈ {restore_drill, failover, tabletop, other}. `bcp_test.outcome` ∈ {pending, pass, partial, fail}. `bcp_test_step.result` ∈ {pending, pass, fail}. `bcp_finding.severity` ∈ {low, medium, high, critical}. `bcp_finding.remediation_state` ∈ {open, in_progress, resolved}.
- **Reuse, do not fork.** `audit_service.record`; `require_permission`/`AuthContext`; `org_session`; the migration `_rls` helper + permission/grant seed from `0016_change_mgmt.py`; the module skeleton from `app/modules/change_mgmt/`; the cross-org resolution guard from `change_mgmt/links.py`; backup reporting reads.
- **Engineering conventions.** Async; typed SQLAlchemy 2; Pydantic v2; logic in services not routes; forward-only additive migration (`down_revision="0016"`); `mypy` + `ruff` clean; frontend strict TS no `any`, state vocab from backend. If Postgres/Redis down: `pg_ctlcluster 16 main start; redis-server --daemonize yes`. Delete any stray `backend/uv.lock`.
